# Technical article types

Choose one primary pattern. Add only sections that serve the article's goal.

## New API or feature introduction

Use for a recently introduced language feature, library capability, runtime API, or web standard.

Typical progression:

1. Support status and stability warning
2. The existing problem or previous approach
3. The feature's role and, when relevant, documented design rationale
4. Definition and minimal example
5. Important behavioral details
6. A reproducible sample and observations
7. Constraints, compatibility, and fallback
8. Summary and references

Require a sample when the feature can be executed in an available environment.

## Hands-on implementation tutorial

Use when readers should build a working result.

Typical progression:

1. Technology overview and finished result
2. Architecture when it materially aids understanding
3. Prerequisites, setup, and installation
4. Incremental implementation by file or responsibility
5. Run and interaction commands
6. Expected output and observed result
7. Operational concerns and extensions
8. Summary and references

Make the tutorial reproducible in a clean environment. Do not omit imports, environment variables, configuration, or startup steps.

## Investigation or comparison

Use to answer a concrete technical question or evaluate alternatives.

Typical progression:

1. The decision or problem being investigated
2. Scope, evaluation criteria, and test environment
3. Standards or concepts required to understand the comparison
4. Observations for each option under equivalent conditions
5. Similarities, differences, and tradeoffs
6. An implementation or decision rubric based on the findings
7. Validation results
8. Summary and references

Separate observed facts from evaluation criteria. Apply comparable conditions to every option.

## Opinion or experience

Use for an engineering practice, retrospective, or reasoned position.

Typical progression:

1. The author's current position and how it developed
2. Practices or experiences grouped by theme
3. Reasons, benefits, limitations, and counterarguments
4. The boundary of what can be generalized
5. What may change in the future
6. Summary and references when external claims appear

First person is appropriate. Do not present personal experience as universal fact.
